# Sachet

Sachet is a scam-message detector for SMS and WhatsApp messages written in Hinglish (Hindi in Roman script mixed with English), Roman Hindi, and English. It combines a TF-IDF + Logistic Regression classifier with a rule layer for OTP/PIN solicitation, and explains each verdict with human-readable red flags.

The name comes from the Hindi word *sachet* (सचेत), meaning "alert" or "vigilant".

## Problem

Most public spam datasets are English, Western, and over a decade old. Indian scam messages differ in three ways that break such models:

1. **Code-mixed language.** Messages switch between Hindi and English mid-sentence, with no standard spelling (`aapka`, `apka`, `apke`).
2. **Region-specific scam types.** KYC expiry, electricity disconnection, UPI "wrong transfer" refunds, parcel/customs holds, "digital arrest" by fake police, and family impersonation from a "new number".
3. **Legitimate messages that look like scams.** Genuine bank OTPs, debit alerts and bill reminders use the same vocabulary as scams (OTP, account, Rs, urgent). A useful detector must not flag them.

## How it works

```
message
   |
   v
text cleaning ----> links -> urltoken, phone numbers -> phonetoken,
   |                amounts -> moneytoken, long/masked numbers -> numtoken
   v
TF-IDF features --> word 1-2 grams  +  character 2-5 grams (char_wb)
   |
   v
Logistic Regression (class_weight="balanced")  -->  scam probability
   |
   v
rule layer ------> if the message ASKS the reader to share an OTP/PIN/CVV
   |               (and is not negated: "do not", "never", "mat", "nahi"),
   |               probability is raised to at least 0.95
   v
verdict  ---------> >= 0.70 SCAM | 0.40-0.70 SUSPICIOUS | < 0.40 LOOKS SAFE
   +
red flags --------> pattern matches shown to the user (link present, KYC request,
                    urgency, prize claim, police/government threat, fee request, ...)
```

**Design decisions**

- **Character n-grams** handle inconsistent Hinglish spelling: `aapka`, `apka` and `apke` share sub-word features.
- **Token normalisation** replaces specific links, numbers and amounts with fixed tokens so the model learns the presence of a pattern (for example, "contains a link") rather than memorising individual fake domains.
- **Masked and real numbers are normalised identically.** Training data has OTPs masked as `XXXXXX` for privacy, while real users paste real digits. Without this, the model learned "masked number = safe, real number = scam" and flagged a genuine HDFC OTP at 90% scam probability. After the fix it scores 7%.
- **Hybrid ML + rules.** A bag-of-words model cannot reliably separate "share the OTP" from "do not share the OTP", since both contain the same tokens. A rule that inspects word order and nearby negation handles this case deterministically, in both English ("share the OTP") and Hinglish ("OTP batao") word order.
- **Balanced class weights** prevent the model from defaulting to the majority class.

## Data

| Source | Safe | Scam | Used in training | Description |
|---|---|---|---|---|
| Synthetic (`messages.csv`) | 359 | 467 | Yes | Template-generated messages covering 35 scam and 35 legitimate patterns, with case and punctuation noise. Generated by `scripts/make_dataset.py` |
| Hand-written (`claude_messages.csv`) | 82 | 214 | Yes | Individually written messages across 14 scam categories, plus difficult legitimate messages (bank alerts, OTPs, family chat). Written with an AI assistant; synthetic, not collected |
| Real (`real_messages.csv`) | 13 | 0 | Yes | Messages actually received, with OTPs, account numbers and order IDs masked |
| Hugging Face (`raw/hf_scam.json`) | 2,906 | 652 | **No** | See below |
| **Total used for training** | **454** | **681** | | **1,135 messages** |

**Why the Hugging Face dataset is excluded.** The [Hinglish & English Financial Scam/Fraud Text Dataset](https://huggingface.co/bolewara/hinglish-scam-text-dataset) is mostly derived from the UCI SMS Spam Collection (UK, circa 2010). Its legitimate messages are almost entirely casual personal chat, while its spam messages are almost entirely formal commercial text. Trained on it, the model learned "formal message containing an amount = scam". Six training configurations were compared (full data, down-weighted to 0.3 and 0.15, legitimate-only, scam-only, excluded):

| Configuration | Test set (36) | Fresh set (16) | Genuine bank alerts flagged |
|---|---|---|---|
| Included, full weight | 36/36 | 12/16 | 4 of 8 |
| Included, weight 0.15 | 36/36 | 12/16 | 4 of 8 |
| **Excluded** | **35/36** | **16/16** | **0 of 8** |

Because bank and payment alerts are the most common SMS an Indian user receives, a high false-positive rate on them makes the tool unusable. The dataset is still merged into `combined.csv` and can be re-enabled by editing `EXCLUDE_SOURCES` in `src/train.py`.

**Held-out evaluation sets** (removed from training data automatically by `build_dataset.py`):

- `test_messages.csv`: 36 hand-written messages (16 scam, 20 legitimate) phrased differently from the training templates.
- `fresh_messages.csv`: 16 everyday Indian messages (bank debit/credit alerts, transaction OTPs, delivery OTPs, and 8 common scam types).

## Results

| Evaluation | Accuracy | Notes |
|---|---|---|
| Validation (20% stratified split of training data) | 98.7% | 0 legitimate messages flagged, 3 of 136 scams missed |
| Test set, model only | 97.2% (35/36) | |
| Test set, model + rule | 97.2% (35/36) | 0 legitimate messages flagged, 1 scam missed |
| Fresh set, model + rule | 100% (16/16) | |

The single test-set error is an investment scam written in a casual, friendly tone with no link, OTP, threat or urgency keyword ("Bhai maine ek app pe 2000 lagaye aur 8000 mile, tu bhi kar...").

These numbers come from small, partly synthetic evaluation sets and should be read as a sanity check, not as an estimate of real-world performance. See [Limitations](#limitations).

## Setup

Requires Python 3.10 or later.

```bash
git clone https://github.com/ama896/sachet.git
cd sachet
python -m venv venv
venv\Scripts\activate          # Windows
# source venv/bin/activate     # macOS / Linux
pip install -r requirements.txt
```

## Usage

**Rebuild the dataset and retrain**

```bash
python scripts/build_dataset.py
python src/train.py
```

`train.py` prints validation metrics, accuracy per data source, results on both held-out sets with a list of misclassified messages, and saves the final model (trained on all non-excluded data) to `models/sachet_model.joblib`.

**Check messages from the command line**

```bash
python src/predict.py
```

```
Message: Aapka SBI account aaj band ho jayega, PAN update karo sbi-pan-kyc.in
  -> SCAM  (scam probability 99%)
     ! Contains a link
     ! Asks to update KYC / PAN / Aadhaar
     ! Threatens to block or cut a service
```

**Run the web app**

```bash
streamlit run src/app.py
```

The app opens at `http://localhost:8501`.

## Adding data

Add messages to `data/real_messages.csv` (columns `text,label`, label is `scam` or `safe`), then rebuild and retrain. Before adding a message, mask personal information: OTPs, phone numbers, account and card numbers, order IDs and names. See `data/README.md` for collection sources and guidelines.

## Limitations

- **Small evaluation sets.** The test and fresh sets contain 36 and 16 messages. One error changes accuracy by roughly 3 and 6 percentage points respectively.
- **Mostly synthetic training data.** About 99% of training messages are synthetic. The model has seen few real scams, so real-world accuracy is likely lower than reported.
- **Evaluation sets are hand-written.** They were written separately from the training data with different phrasing, but by the same process, so they may share stylistic patterns the model can exploit.
- **Bag-of-words model.** The classifier ignores word order beyond bigrams. Negation and context ("my friend got this scam message") are only partly handled, through the OTP rule.
- **Text only.** Links are not resolved or checked against blocklists, and sender IDs are not used.
- **Script coverage.** Devanagari-script Hindi is not represented in the training data.

## Roadmap

- Collect and label 200+ real messages, and report accuracy on real messages separately.
- Add sender-ID features (registered bank headers such as `AX-HDFCBK` versus 10-digit mobile numbers).
- Check extracted domains against known-legitimate lists (for example, official bank domains).
- Compare against a multilingual transformer (for example, MuRIL or IndicBERT) fine-tuned on the same data.
- Deploy the web app publicly.
